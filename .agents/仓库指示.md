# MeloongCore 仓库指示

## 技术栈

- 使用 C# 13、Nullable、Implicit Usings 和 PolySharp。
- `Shared` 面向 .NET Standard 2.0，不依赖 WPF。
- `Wpf` 与 `Tests` 面向 .NET Framework 4.8。
- 保持现代、清晰的 C# 写法，但不做过度抽象、优化或防御性检查。
- 简化类结构，少留空行，但保留必要的注释。
- 修改已有代码时优先保持最小改动，并删除修改后确定无用的内容。
- 不添加只有一两行的小型辅助方法；仅有一个引用的方法或变量应积极考虑内联。

## C# 代码风格

- 大括号不换行；变量名使用小驼峰，类型、属性和方法名使用大驼峰。
- 没有 `else`、逻辑较短且仅含一条语句的 `if` 写在一行并省略大括号，例如 `if (flag) break;`；`if` 一旦换行，必须添加大括号。
- 单行大括号内的内容前后不加空格，例如 `{element}`。
- 行尾注释与代码之间、`//` 与注释正文之间各留一个空格，例如 `break; // 注释`。XML 文档注释引用参数时使用 `<paramref name="..."/>`。
- 优先使用 C# 13 下更简洁且清晰的写法，例如 using 声明、本地函数和集合表达式。
- 使用 `""` 表示空字符串，不使用 `string.Empty`。

## 项目边界

- `Shared` 只存放可跨产品复用的通用能力，不得依赖具体上层应用的业务领域或 UI 页面。
- Windows 与 WPF 特有功能优先放入 `Wpf`，避免破坏 Shared 的 macOS 可用性。
- `Tests` 负责保护 Shared 与 Wpf 的公共行为，不应反向依赖引用本库的上层应用项目。
- 新增工具前先检查现有 Extensions、General 和 Utils，避免重复实现。
- 公共 API 会影响所有引用方，修改签名或语义前应检查兼容性。

## 仓库安全

- MeloongCore 是独立 Git 仓库，提交内容不得依赖特定引用方的私有目录结构或开发流程。
- 构建 WPF 工程时使用 Visual Studio 2022 的 `MSBuild.exe`。
- 保留用户已有的未提交修改，不覆盖或清理无关文件。
- 不提交密钥、访问令牌、构建产物、测试结果或本地环境文件。
